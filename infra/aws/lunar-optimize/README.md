# Lunar Optimize on AWS (optimize.projectlunar.ai)

Prepared 2026-10-21, not deployed. Nothing here has been run against AWS. It is a separate stack in the lunar
account (us-west-2) that shares nothing with the Studio box or the HVAC box (the HVAC box's `openseo-lunar` container
and `seo.projectlunar.ai` stay as they are; the LunarGEO scanner depends on them).

## What it creates (only when deployed)

| Resource | Notes |
|---|---|
| EC2 `t3.small` (Ubuntu 24.04) | SSM Session Manager only, no SSH, no key pair. 4 GB swap for the start-time build. |
| Security group | Inbound 80 and 443 only. |
| IAM role | SSM core, `codecommit:GitPull` on open-seo, `secretsmanager:GetSecretValue` on `lunar-optimize/app` only. |
| Elastic IP + Route53 A record | `optimize.projectlunar.ai` in zone `Z02101901H58WZ0VD505N`. |
| 30 GB gp3 root, encrypted | Holds the SQLite store (D1 emulation) in a Docker volume; kept on instance termination. |

The app runs as the existing open-seo self-host container (`Dockerfile.selfhost`), built on the host from this branch,
behind Caddy, which gets and renews the TLS certificate itself.

**Database:** the self-host container's default store (SQLite via the D1 emulation, on the EBS volume). The app's
Postgres mode only works through Cloudflare's Hyperdrive binding, so it is not used here. Back up with EBS snapshots.

## Settings (Secrets Manager `lunar-optimize/app`, names only)

Fixed in `render-env.sh`, not secret: `AUTH_MODE=hosted`, `BETTER_AUTH_URL`, `ALLOWED_HOST`,
`LUNAR_OPTIMIZE_CHECKOUT_ENABLED=false` (checkout stays off), telemetry off.

| Name | Status |
|---|---|
| `BETTER_AUTH_SECRET` | Generated by `prepare-secret.sh`. |
| `DATAFORSEO_API_KEY` | Copied by `prepare-secret.sh` from HVAC `hvac-automations/openseo-env` (already paid). Without it the app runs on labelled sample data. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | **Required by hosted mode** (Google sign-in and Search Console). Not available yet. |
| `LOOPS_API_KEY`, `LOOPS_TRANSACTIONAL_VERIFY_EMAIL_ID`, `LOOPS_TRANSACTIONAL_RESET_PASSWORD_ID` | Sign-up verification and password reset email (the app sends through Loops). Not available. SES in the lunar account has no verified identity and is in sandbox, so it is not a drop-in. |
| `AUTUMN_SECRET_KEY` and the `AUTUMN_*` feature and plan ids | Hosted mode meters every DataForSEO call through Autumn, so these are needed even with checkout off. Not available. |
| `OPENROUTER_API_KEY` | Optional, AI chat features. |

## Deploy (when approved)

```bash
bash infra/aws/lunar-optimize/prepare-secret.sh                    # BETTER_AUTH_SECRET + DATAFORSEO_API_KEY
printf %s "$VALUE" | bash infra/aws/lunar-optimize/prepare-secret.sh GOOGLE_CLIENT_ID   # one per missing name
aws cloudformation deploy --profile lunar --region us-west-2 --stack-name lunar-optimize-host \
  --template-file infra/aws/lunar-optimize-host.yaml --capabilities CAPABILITY_NAMED_IAM \
  --parameter-overrides VpcId=<vpc> SubnetId=<public subnet>
```

Update later: SSM into the instance, `git -C /opt/lunar-optimize/src pull`, then rerun `bootstrap.sh` with
`LO_DOMAIN`, `LO_SECRET` and `LO_REGION` set.
